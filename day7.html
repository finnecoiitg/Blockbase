Day 7

Connecting to a Frontend

You have a smart contract deployed on Sepolia. Right now the only way to interact with it is through Remix or Etherscan’s Write Contract tab — tools built for developers, not users. A real dApp needs a frontend: a webpage that anyone can open, connect their wallet to, and use without knowing what Solidity is.

Today you build exactly that. By the end of this session you will have a working HTML page that connects to your ERC-20 token on Sepolia, reads its data, and lets you send tokens — all from a browser, with no backend server involved.

The dApp stack

A decentralised application has three layers. Understanding where each one sits makes every code decision easier to reason about.

Layer What it does Who controls it
Frontend
HTML / CSS / JS		 The interface the user sees. Renders data, accepts inputs, triggers actions. The developer (you). Can be hosted anywhere — GitHub Pages, IPFS, a normal web server.
ethers.js
JavaScript library 		Translates your JavaScript calls into Ethereum transactions and RPC requests. Handles all the encoding/decoding. Open-source library. You include it via CDN or npm.
MetaMask
Browser wallet 		Holds the user’s private key. Signs transactions on their behalf. Connects to the Ethereum network via its own RPC node. The user. Your code never sees the private key.
Smart contract
On Sepolia 		The actual logic and storage. Immutable. Runs on every validator node in the network. The blockchain. Nobody — once deployed, even you can’t change it.

The flow for a write operation looks like this: the user fills in a form and clicks a button → your JavaScript calls contract.transfer(...) via ethers.js → ethers.js encodes the call and passes it to MetaMask → MetaMask shows the user a confirmation popup with the gas estimate → the user clicks Confirm → MetaMask signs the transaction with the user’s private key and broadcasts it to the network → the transaction lands in a block → ethers.js resolves the await tx.wait() promise → your UI updates.

Read operations are simpler: no signing, no MetaMask popup, no gas. Your JavaScript calls a view function → ethers.js sends an RPC request directly to MetaMask’s node → the result comes back as a JavaScript value → you display it.

Provider vs signer

These two concepts appear everywhere in ethers.js code and are consistently confused at first. They are different things.

A provider is a read-only connection to the network. It can fetch balances, call view functions, and listen for events. It does not have any signing capability. When you create a provider from MetaMask, you are essentially borrowing MetaMask’s connection to its node — but not its keys.

A signer wraps a provider and adds the ability to sign transactions. It represents a specific wallet address. When you call a state-changing function through a signer-connected contract, MetaMask pops up to ask the user to approve the signature. 

// Provider: read-only, no wallet needed
const provider = new ethers.providers.Web3Provider(window.ethereum);

// Signer: wraps the provider, tied to a specific account
const signer = provider.getSigner();

When you connect a contract to a provider, calling any function on it is free and instant — no MetaMask popup. When you connect a contract to a signer, calling a state-changing function opens MetaMask. Use the right one for the right job: read-only calls should use the provider, so the user isn’t asked to approve things unnecessarily.

What is an ABI?

Your smart contract’s bytecode is stored on-chain. To call a specific function in that bytecode, ethers.js needs to know the function’s name, its parameter types, and its return types — so it can encode the call correctly and decode the response. This description is the ABI.

The full JSON ABI is generated by the Solidity compiler and available in Remix (Compiler tab → after compiling → click the ABI button to copy it). It looks like this: 

[
  {
    "inputs": [{ "internalType": "address", "name": "account", "type": "address" }],
    "name": "balanceOf",
    "outputs": [{ "internalType": "uint256", "name": "", "type": "uint256" }],
    "stateMutability": "view",
    "type": "function"
  },
  ...
]

For a large contract this JSON is hundreds of lines. ethers.js also accepts a much more readable shorthand called the human-readable ABI — just the function signatures as strings, the same way they appear in Solidity interfaces: 

const ABI = [
    "function name() view returns (string)",
    "function symbol() view returns (string)",
    "function totalSupply() view returns (uint256)",
    "function balanceOf(address) view returns (uint256)",
    "function transfer(address to, uint256 amount) returns (bool)",
    "event Transfer(address indexed from, address indexed to, uint256 value)"
];

This is what you will use today. It lists only the functions you actually call, which is fine — you don’t need to include functions your frontend doesn’t use.

ethers.js via CDN

For this course you do not need Node.js, npm, or any build tooling. One script tag is enough: 

<script src="https://unpkg.com/ethers@5.7.2/dist/ethers.umd.min.js"></script>

Place this at the bottom of your HTML body, before your own script. It makes the ethers object available globally. In production projects ethers.js is installed via npm and imported as a module, but the CDN version behaves identically for our purposes.

The five patterns you need

All ethers.js frontend code is a combination of five patterns. Learn these and you can build any dApp read/write interface.

1. Connect wallet and get a signer:

const provider = new ethers.providers.Web3Provider(window.ethereum);
await provider.send("eth_requestAccounts", []);  // triggers MetaMask popup
const signer = provider.getSigner();
const address = await signer.getAddress();       // "0xYourWalletAddress"

2. Connect to a contract:

// Read-only — use provider
const readContract = new ethers.Contract(CONTRACT_ADDRESS, ABI, provider);

// Read/write — use signer
const writeContract = new ethers.Contract(CONTRACT_ADDRESS, ABI, signer);

3. Call a view function (free, no MetaMask popup): 

const balance = await readContract.balanceOf(userAddress);
// balance is a BigNumber — convert before displaying:
const readable = ethers.utils.formatUnits(balance, 18);  // "1000000.0"

4. Send a transaction (costs gas, MetaMask popup): 

// parseUnits converts a human-readable number to the 18-decimal representation
const amount = ethers.utils.parseUnits("10", 18);  // 10 tokens → BigNumber
const tx = await writeContract.transfer(recipientAddress, amount);
await tx.wait();  // waits until the transaction is mined

5. Listen for events:

readContract.on("Transfer", (from, to, amount, event) => {
    console.log(`${from} sent ${ethers.utils.formatUnits(amount, 18)} tokens to ${to}`);
    // This fires every time a Transfer event is emitted by your contract
    // event.transactionHash gives you the tx hash
});

The BigNumber type appears throughout ethers.js because JavaScript’s native number type cannot safely represent integers as large as token balances (up to 1077). Never do arithmetic on BigNumbers with + or * — use their methods (.add(), .mul()) or convert first. When displaying to the user, always call ethers.utils.formatUnits(bn, 18). When accepting input from the user, always call ethers.utils.parseUnits(string, 18).

The complete dashboard

Create a new file called token-dashboard.html anywhere on your computer. Write out the following — typing it line by line is strongly encouraged over pasting, especially the JavaScript section: 

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>My Token Dashboard</title>
    <style>
        body { font-family: Arial, sans-serif; max-width: 600px; margin: 40px auto; padding: 0 20px; }
        button { padding: 10px 20px; margin: 8px 0; cursor: pointer; background: #6366f1; color: white; border: none; border-radius: 6px; }
        input { padding: 8px; margin: 4px 0; width: 100%; box-sizing: border-box; border: 1px solid #ccc; border-radius: 4px; }
        .card { border: 1px solid #e5e7eb; border-radius: 8px; padding: 20px; margin: 16px 0; }
        #status { color: #6b7280; font-size: 14px; margin-top: 8px; }
    </style>
</head>
<body>
    <h1>My Token Dashboard</h1>

    <div class="card">
        <h2>Wallet</h2>
        <button onclick="connectWallet()">Connect MetaMask</button>
        <p id="walletAddress">Not connected</p>
        <p>Your balance: <strong id="userBalance">—</strong></p>
    </div>

    <div class="card">
        <h2>Token Info</h2>
        <p>Name: <strong id="tokenName">—</strong></p>
        <p>Symbol: <strong id="tokenSymbol">—</strong></p>
        <p>Total Supply: <strong id="totalSupply">—</strong></p>
    </div>

    <div class="card">
        <h2>Send Tokens</h2>
        <input type="text" id="recipientAddress" placeholder="Recipient address (0x...)">
        <input type="number" id="sendAmount" placeholder="Amount to send">
        <button onclick="sendTokens()">Send</button>
        <p id="status"></p>
    </div>

    <script src="https://unpkg.com/ethers@5.7.2/dist/ethers.umd.min.js"></script>
    <script>
        // ⚠️ Replace with your own values from Day 6
        const CONTRACT_ADDRESS = "0xYOUR_CONTRACT_ADDRESS_HERE";
        const ABI = [
            "function name() view returns (string)",
            "function symbol() view returns (string)",
            "function totalSupply() view returns (uint256)",
            "function balanceOf(address) view returns (uint256)",
            "function transfer(address to, uint256 amount) returns (bool)",
            "event Transfer(address indexed from, address indexed to, uint256 value)"
        ];

        let provider, signer, contract;

        async function connectWallet() {
            provider = new ethers.providers.Web3Provider(window.ethereum);
            await provider.send("eth_requestAccounts", []);
            signer = provider.getSigner();
            const address = await signer.getAddress();
            document.getElementById("walletAddress").textContent = address;

            contract = new ethers.Contract(CONTRACT_ADDRESS, ABI, signer);

            document.getElementById("tokenName").textContent = await contract.name();
            document.getElementById("tokenSymbol").textContent = await contract.symbol();

            const supply = await contract.totalSupply();
            document.getElementById("totalSupply").textContent =
                ethers.utils.formatUnits(supply, 18) + " tokens";

            await refreshBalance(address);

            contract.on("Transfer", async (from, to, amount) => {
                const myAddr = await signer.getAddress();
                if (to.toLowerCase() === myAddr.toLowerCase()) {
                    await refreshBalance(myAddr);
                    setStatus("Received " + ethers.utils.formatUnits(amount, 18) + " tokens!");
                }
            });
        }

        async function refreshBalance(address) {
            const bal = await contract.balanceOf(address);
            const sym = await contract.symbol();
            document.getElementById("userBalance").textContent =
                ethers.utils.formatUnits(bal, 18) + " " + sym;
        }

        async function sendTokens() {
            const recipient = document.getElementById("recipientAddress").value;
            const amount = document.getElementById("sendAmount").value;

            if (!recipient || !amount) { setStatus("Please fill in all fields."); return; }

            try {
                setStatus("Sending transaction...");
                const tx = await contract.transfer(
                    recipient,
                    ethers.utils.parseUnits(amount, 18)
                );
                setStatus("Waiting for confirmation...");
                await tx.wait();
                setStatus("Sent! Tx: " + tx.hash);
                await refreshBalance(await signer.getAddress());
            } catch (err) {
                setStatus("Error: " + err.message);
            }
        }

        function setStatus(msg) {
            document.getElementById("status").textContent = msg;
        }
    </script>
</body>
</html>

Walking through the JavaScript

The module-level variables — provider, signer, and contract — are declared outside any function so that all functions share them. connectWallet() initialises all three. The other functions (sendTokens, refreshBalance) rely on contract and signer already being set, which is why you must click Connect before doing anything else.

connectWallet does five things in order: creates a provider from MetaMask, requests the user’s accounts (this is the popup), gets a signer for the connected account, creates a contract instance tied to that signer, and then loads all the display data. The event listener is registered here too — once per connection. Task 3 covers how that works in detail.

refreshBalance calls balanceOf with a specific address and updates the display. It is a separate function because you call it in two places: once after connecting, and again after a successful send. Rather than duplicating the DOM update code, you extract it.

sendTokens reads both input fields, validates that they are filled, and then calls contract.transfer(). The call is wrapped in try/catch because many things can go wrong: the user rejects the MetaMask popup, the recipient address is malformed, or the sender doesn’t have enough tokens. All of these throw exceptions — catch them and display the error message rather than letting the page crash silently.

The await tx.wait() call is important. Without it, your code would mark the send as complete the moment the transaction was submitted to the mempool — not when it was actually mined. The balance would be wrong. tx.wait() resolves only after the transaction appears in a block.

Running it

  1. Replace CONTRACT_ADDRESS with your actual deployed Sepolia address from Day 6.
  2. Open token-dashboard.html directly in your browser (double-click the file — no server needed).
  3. Make sure MetaMask is on the Sepolia network. If it’s on mainnet, the contract address will not be found and all calls will fail.
  4. Click Connect MetaMask and approve.
  5. Token name, symbol, and total supply load. Your balance appears.
  6. Enter a classmate’s address in the Send field. Enter a small amount (1, 5, 10 — whatever). Click Send. MetaMask opens. Confirm it.
  7. Wait for the “Sent!” status message. Your balance updates automatically.

How event listening works

In the dashboard, this block runs once, inside connectWallet: 

contract.on("Transfer", async (from, to, amount) => {
    const myAddr = await signer.getAddress();
    if (to.toLowerCase() === myAddr.toLowerCase()) {
        await refreshBalance(myAddr);
        setStatus("Received " + ethers.utils.formatUnits(amount, 18) + " tokens!");
    }
});

Under the hood, ethers.js subscribes to Ethereum logs — the on-chain record of every event emitted. Every time the network mines a new block that contains a Transfer event from your contract, MetaMask’s node notifies ethers.js, which decodes the event data and calls your callback with the three arguments.

The address comparison uses .toLowerCase() on both sides. Ethereum addresses are case-insensitive at the protocol level, but the casing varies depending on the source — MetaMask returns checksummed addresses (mixed case), event data may come back in lowercase, and user input could be anything. Always normalise before comparing.

The check if (to.toLowerCase() === myAddr.toLowerCase()) filters out transfers the connected wallet sent. Every transfer event fires the callback regardless of direction. Without the filter, your balance would refresh and show a notification both when you receive tokens and when you send them — which is confusing, since the send path already handles its own UI update.

One thing to know: contract.on() keeps the subscription alive indefinitely. If the user disconnects or the page reloads, it disappears. In production apps you would also call contract.off("Transfer", handler) on cleanup to avoid memory leaks — but for a session-based page like this one, it is not a concern.

Challenge — The balance checker

Add a fourth card to the dashboard. It should let anyone type in any Ethereum address and see how many of your tokens that address holds — without needing MetaMask to be connected. This is a pure read operation.

Add this HTML after the “Send Tokens” card:

<div class="card">
    <h2>Check Any Balance</h2>
    <input type="text" id="checkAddress" placeholder="Any Ethereum address (0x...)">
    <button onclick="checkBalance()">Check Balance</button>
    <p id="checkResult">—</p>
</div>

Now write the checkBalance() function. A few things to think through before writing it:

  • This function should work even if the user has not connected their wallet yet. That means it cannot rely on contract (which is only set after connectWallet runs). It needs its own read-only contract instance built from the provider alone.
  • But provider is also only set after connectWallet. You need a provider that always exists — even before wallet connection.
  • MetaMask injects window.ethereum into every page, regardless of whether the user has connected. You can create a provider from it at any time: new ethers.providers.Web3Provider(window.ethereum). This provider can read from the network without any wallet approval.

With that in mind, here is the function — try writing it yourself first, then compare: 

async function checkBalance() {
    const address = document.getElementById("checkAddress").value.trim();
    if (!address) { document.getElementById("checkResult").textContent = "Enter an address."; return; }

    // Build a read-only contract without needing connectWallet to have run
    const readProvider = new ethers.providers.Web3Provider(window.ethereum);
    const readContract = new ethers.Contract(CONTRACT_ADDRESS, ABI, readProvider);

    try {
        const bal = await readContract.balanceOf(address);
        const sym = await readContract.symbol();
        document.getElementById("checkResult").textContent =
            ethers.utils.formatUnits(bal, 18) + " " + sym;
    } catch (err) {
        document.getElementById("checkResult").textContent = "Error: " + err.message;
    }
}

Test it with three addresses: your own wallet (should match the balance shown in the Wallet card), a classmate’s address (should show what you sent them), and a random address from Etherscan (should return 0.0).

What you now have

A single HTML file, opened directly in a browser, that connects to a live smart contract on a real blockchain, reads live data, sends transactions, and reacts to on-chain events in real time. No backend. No database. No server. The contract is the backend.

This is the complete Web3 development loop: write the contract in Solidity → deploy it to a network → build a frontend that talks to it via ethers.js. Everything from Day 1 to today was building toward this.

Where to go from here

Plain HTML with a CDN script tag gets you surprisingly far, but real production dApps move to a more structured setup. The natural progression after today:

Tool What it adds over today’s setup
Hardhat A local blockchain, automated tests, and deployment scripts. Replaces the Remix workflow entirely for serious projects.
wagmi React hooks that wrap ethers.js. Handles wallet connection state, network switching, and transaction lifecycle with much less boilerplate than raw ethers.js.
RainbowKit A polished wallet connection modal that supports MetaMask, WalletConnect, Coinbase Wallet, and more — all wired up with one component.
ethers.js v6 The current major version. The API is slightly different from v5 (which you used today): BrowserProvider instead of Web3Provider, parseUnits directly on ethers rather than ethers.utils. The concepts are identical; only the method paths changed.
